# Architecture

## Overview

```
                 ┌──────────────────── one server (Uzbekistan) ────────────────────┐
 browser ──TLS──►│ Caddy ──► web (Node, React Router SSR) ──► api (Go) ──► Postgres │
 Telegram ◄──────│             └──── /media/* served directly by Caddy ◄─ media dir │
                 │                                worker (Go) ─┘   bot (Go) ─┘    │
                 └─────────────────────────────────────────────────────────────────┘
```

- **web** renders every page on the server (fast first paint, SEO, works without JS) and calls the API through the generated client.
  Browsers talk only to `web` and `/media`; `/v1/*` is proxied to `api` for client-side requests (likes, compose, SSE).
- **api** owns all data and rules: auth, posts, notes, articles, comments, votes, follows, moderation, search.
- **worker** runs background jobs from a Postgres queue (`FOR UPDATE SKIP LOCKED`): ranking every 60 s, link previews, image resizing,
  notifications, scheduled articles, monthly threads.
- **bot** is the Telegram bot (long polling): account linking, notifications, channel autopost.
- **Postgres** is the only stateful service besides the media folder. No Redis; caches are in-process.

## Contract-first API

`packages/api-spec/openapi.yaml` → `oapi-codegen` (Go strict server interfaces) + `openapi-typescript` (TS client).
Both are generated by `pnpm gen` and committed; CI fails if they're out of date. This keeps web and API in sync across many contributors.

## Domains (`apps/api/internal/`)

| Package    | Owns                                                                  |
| ---------- | --------------------------------------------------------------------- |
| `auth`     | GitHub/Google OAuth, Telegram login, sessions, CSRF                   |
| `users`    | profiles, stack, pinned repos, badges, export, deletion               |
| `social`   | follows (users, tags), mutes, blocks, muted words, visibility filter  |
| `links`    | link/text/Savol/Koʻrsat posts, URL canonicalization, dedupe           |
| `notes`    | notes, replies, likes, reposts, quotes, bookmarks, link previews      |
| `articles` | drafts, versions, publishing, series, featuring                       |
| `comments` | threaded comments for links and articles                              |
| `votes`    | votes and karma                                                       |
| `rank`     | Top ranking (pure functions + worker job)                             |
| `timeline` | Following timeline (fan-out on read, keyset pagination)               |
| `media`    | upload, re-encode, resize, content-addressed storage                  |
| `notify`   | in-app + Telegram notifications                                       |
| `mod`      | flags, reports, moderator actions, public mod log, spam rules         |
| `search`   | Postgres full-text search on normalized text                          |
| `feeds`    | RSS/Atom                                                              |
| `fetch`    | SSRF-safe outbound HTTP                                               |
| `translit` | Uzbek Latin ⇄ Cyrillic (shares test vectors with `packages/translit`) |

## Key decisions

- **One server, no paid services.** Fits a community budget; scale up the machine before scaling out.
- **Server-side rendering + progressive enhancement.** Pages are readable and core actions work without JS.
- **Fan-out on read for timelines.** Simple and correct at our size; revisit with measurements.
- **Images are always re-encoded** (strips metadata, blocks malicious files).
- **Data stays in Uzbekistan** (hosting choice, matching local personal data rules).
- **AGPL-3.0** so hosted forks stay open.
